# KarlLang v10 – 핵심 프로젝트 명세서 (개발자용 PRD 요약)

## 1. 핵심 기능 로직

### 1.1 학습 모드 구조

- **모드 종류**
  - `typing_de` : 뜻 → 독일어 타이핑
  - `card` : 한쪽(질문) → 다른쪽(정답) 카드 플립
  - `copy` : 따라쓰기(깜지 모드 전신, 현재는 일반 copy와 cram 분리)
  - `training / cram` : 훈련소에서 선택된 단어들을 반복 따라쓰기 전용 모드

- **공통 상태**
  - `APP_STATE`  
    - `phase`: `"READY" | "QUESTION" | "ANSWER" | "FINISHED"`
    - `currentCard`: 현재 단어(SRS 포함)
    - `queue`: 이번 세션 대상 단어 리스트
    - `completed`: 이번 세션에서 처리한 카드 수
    - `totalTarget`: 이번 세션 목표 카드 수
    - `newCount`, `reviewCount`: 새 단어/복습 단어 개수
    - `currentView`: `"study" | "training" | "mistakes" | "bookmark" | "search" | "settings" ...`

- **훈련소 상태**
  - `TRAINING_MODE_ACTIVE: boolean` – 훈련소 모드 on/off
  - `TRAINING_MODE_KIND: "none" | "typing" | "copy" | "mix" | "cram"`
  - `TRAINING_MIX_WORDS`, `TRAINING_MIX_INDEX`, `TRAINING_MIX_STEP` – mix 모드용(현재 주력은 cram)
  - `TRAINING_CRAM_WORDS`: 깜지 대상 단어 배열
  - `TRAINING_CRAM_INDEX`: 현재 몇 번째 단어인지
  - `TRAINING_CRAM_REPEAT_TOTAL`: 이 단어를 몇 번 쓸 건지 (1/3/5)
  - `TRAINING_CRAM_REPEAT_INDEX`: 현재 몇 회째인지(0-based)

### 1.2 SRS(Spaced Repetition) 로직

- **데이터 버전**
  - `DATA_VERSION = "goethe_a1_full_v1"`  
  - settings에 `dataVersion` 저장, 버전 바뀌면 해당 언어 SRS/통계/wordStats 리셋

- **레벨 & 인터벌**
  - `SRS_LEVELS = [0, 1, 2, 3, 4, 5]`
  - `SRS_INTERVALS = [0, 1, 2, 4, 7, 15]` (일 단위)
  - `nowDay()`로 오늘 날짜를 일(day) 단위 epoch로 계산

- **per-word SRS 상태**
  - `getSrsKey(wordId, lang)` → `"karllang_word_<lang>_<id>"`
  - `getWordState(word)`  
    - 로컬스토리지에서 상태 로드, 없으면 `{ level:0, isNew:true, lastReviewed:0, nextDue:0 }`
  - `saveWordState(state)`  
    - `level`, `lastReviewed`, `nextDue`, `isNew` 저장

- **큐 구성 (`buildQueue`)**
  1. **필터링**
     - CEFR 필터  
       - `SETTINGS.newWordCefr` (`"all" | "A1"...`)  
       - `w.cefr`와 비교, `all` 아니면 동일 CEFR만 통과
     - 카테고리 필터  
       - `SETTINGS.newWordCategory` (`"all" | "exam" | "basic" | "daily" | "travel" | "work" | "smalltalk" ...`)  
       - `w.tags` 배열에 해당 값 포함 여부로 필터
     - UI 언어 기준 의미 존재 여부  
       - `getMeaning(w)`가 비어 있으면 제외

  2. **새 단어 vs 복습**
     - `isNew === true` → `newWords`에
     - `!isNew && nextDue <= today` → `due`에

  3. **복습 정렬**
     - `level` 오름차순 → `nextDue` 오름차순

  4. **새 단어 셔플**
     - `shuffleArray(newWords)` (Fisher–Yates)  
       → “A 지옥(알파벳 앞부분 몰림)” 방지

  5. **목표 개수만큼 큐 채우기**
     - `target = SETTINGS.goalTyping` (기본값 5)
     - `due` 먼저 채우고 부족분을 `newWords`에서 채움
     - `APP_STATE.queue` 세팅 + 카운터 초기화

	•	현재 반복 단계에 맞는 ghost 적용

function applyCramGhost(word) {
  const full = buildGermanForm(word);
  const ghostType = getGhostTypeForCram(
    TRAINING_CRAM_REPEAT_INDEX,
    TRAINING_CRAM_REPEAT_TOTAL
  );

  if (ghostType === "FULL") {
    DOM.copyGhost.innerHTML = buildFullGhostHtml(full);
  } else if (ghostType === "FIRST") {
    DOM.copyGhost.innerHTML = buildFirstLetterGhostHtmlForCram(full);
  } else {
    DOM.copyGhost.textContent = "";
  }
}

3. 중복 제거 & 태깅 파이프라인 (B1 기준)

3.1 원본 → 정제 → dedup 흐름
	1.	PDF에서 RAW 추출
	•	RAW_DE_B1_SOURCE 형태(별도 Node 스크립트)
	2.	정제(clean)
	•	텍스트 오류/잘못된 POS/접두사·접미사 타입 정리
	•	예: "-weise" → pos: "Adverb" + 의미에 “(접미사)” 명시
	3.	앱 스키마로 변환
	•	raw_de_b1.js → words_de_b1.js
	•	변환 시:
	•	lemma/pos/cefr/tags/meanings/examples/gender/plural/conj/meta/id 구조로 매핑
	•	관사 포함 lemma 처리(명사)
	4.	A1/A2와 교차 중복 제거
	•	A1/A2 + B1 로드 후, 중복 key 기준으로 B1에서 제거
	•	중복 기준: 실제 구현은 정리 스크립트 참고
(실제 작업 결과: B1 원본 2485 → dedup 후 1446)
	•	결과 파일: words_de_b1_nodup.js → 내용 최종적으로 words_de_b1.js에 통합

3.2 태깅 파이프라인
	1.	태깅용 JSON 생성
	•	B1 전체 단어 id 리스트 기반
	•	LLM으로 카테고리 태그 부여(basic/daily/travel/work 등)
	•	결과: b1_tags_all.json
	•	구조: { id, tags: ["exam", "daily", ...] }[]
	2.	검증 스크립트 (check_b1_tags.js)
	•	허용 태그 집합: ["exam", "basic", "daily", "travel", "work"]
	•	b1_tags_all.json 로드 후:
	•	허용되지 않은 태그 없는지 검사
	•	tags 빈 배열인 항목 개수/리스트 출력
	•	태그 id가 WORDS_DE_B1 안에 모두 존재하는지 검증
	•	반대로 B1의 모든 단어가 태그 파일에도 존재하는지 확인
	3.	합치기
	•	words_de_b1.js 로드 후
	•	b1_tags_all.json의 tags를 병합, exam은 기본값처럼 취급
	•	태그 없는 단어는 최소 "exam" 하나는 갖도록 후처리(현재 일부는 빈 배열로 남아 있음 → 향후 보완 여지)
