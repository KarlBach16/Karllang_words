1. 목적

목표
	•	타이핑 기반 단어 암기 엔진
	•	다국어 UI / 다국어 뜻 지원
	•	단기 목표: 독일어 A1–B1
	•	장기 목표: A1–C2 + 다국어 확장
	•	데이터 구조 변경 없이 확장 가능한 스키마 확정

KarlLang은 “카드 보기/게임형”이 아닌
성인 학습자용 생산(recall) 중심 단어 암기 플랫폼이다.

⸻

2. Word 객체 스키마

각 단어는 하나의 의미 단위(sense-level entry) 로 저장한다.

{
  id: "bank_nf_1",
  lemma: "Bank",
  pos: "Nomen",
  gender: "die",
  plural: "Banken",
  cefr: "A1",
  tags: ["exam", "finance"],
  conj: { /* Verb일 때만 */ },
  meanings: {
    de: "Bank",
    ko: "은행",
    en: "bank"
  },
  examples: ["Ich gehe zur Bank."],
  meta: { }
}


⸻

2.1 필수 필드
	•	id : 문자열, 기술용 고유 식별자
	•	lemma : 표제어 (원어 표기 유지, 대소문자/움라우트 허용)
	•	pos : 품사 (3번 enum 중 하나)
	•	cefr : "A1" | "A2" | "B1" | "B2" | "C1" | "C2"
	•	tags : 문자열 배열
	•	meanings : 언어 코드 → 한 줄 뜻
	•	examples : 예문 배열 (보통 1개)

⸻

2.2 선택 필드
	•	gender : 명사일 때만 "der" | "die" | "das"
	•	plural : 명사 복수형 (없으면 필드 생략)
	•	conj : 동사 활용 (Verb일 때만)
	•	meta : 통계 / 출처 / SRS 메타데이터
	•	(예약) sense, override, orthography, notes (9번 참조)

선택 필드는 “빈 문자열” 사용 금지 → 없으면 생략

⸻

2.3 conj 구조 (Verb 전용)

conj: {
  pres_ich: "ich gehe",
  pres_du: "du gehst",
  pres_er: "er/sie/es geht",
  praet: "ging",
  part2: "gegangen",
  aux: "sein" // 선택, 확장 대비
}

	•	Verb가 아니면 conj 필드는 존재하지 않는다.

⸻

3. pos 허용값 (고정 enum)

다음 값 외에는 허용하지 않는다.
	•	Nomen
	•	Verb
	•	Adjektiv
	•	Adverb
	•	Präposition
	•	Konjunktion
	•	Pronomen
	•	Artikel
	•	Numerale
	•	Interjektion

확장 시 이 목록만 수정, 데이터 생성 프롬프트도 함께 수정한다.

⸻

4. tags 정책

4.1 목적 태그 (고정 5개)
	•	exam : 시험 공식/준공식 어휘
	•	basic : 숫자·색·가족·신체·시간 등
	•	daily : 일상 회화 핵심 어휘
	•	travel : 여행·교통·길 찾기
	•	work : 직장·업무·비즈니스

규칙:
	•	철자 고정
	•	복수 사용 가능
예: ["exam", "basic", "daily"]

⸻

4.2 도메인 태그 (자유)
	•	예: finance, public_transport, smalltalk
	•	소문자 ASCII
	•	공백 대신 _ 권장

⸻

5. meanings 규칙 (LOCK)

meanings: {
  de: "Bank",
  ko: "은행",
  en: "bank",
  es: "banco",
  fr: "banque",
  it: "banca",
  pt: "banco",
  ja: "銀行",
  zh: "银行",
  ru: "банк"
}

규칙:
	•	key = UI 언어 코드
	•	value = 뜻 한 줄
	•	❌ 설명문 / 괄호 / 문법 노트 / 예문 금지
	•	설명이 필요하면 sense.label 사용
	•	영어 동사 뜻은 절대 to 붙이지 않음
	•	go, be, have, eat

⸻

6. id 규칙 (LOCK)

6.1 공통 규칙
	•	ASCII 소문자 + 숫자 + _
	•	특수문자/움라우트/악센트 ❌
	•	id는 기술 식별자, 의미는 lemma + sense

⸻

6.2 lemma → translit 규칙 (id 생성 시)
	•	ä → ae
	•	ö → oe
	•	ü → ue
	•	ß → ss
	•	대문자 → 소문자

예:
	•	Mädchen → maedchen
	•	Fuß → fuss
	•	Über → ueber

⸻

6.3 품사별 패턴

품사	패턴	예시
Nomen	{lemma}_n{성코드}_{번호}	bank_nf_1
Verb	{lemma}_v	gehen_v
Adjektiv	{lemma}_adj	schnell_adj
Adverb	{lemma}_adv	heute_adv
Präposition	{lemma}_prep	mit_prep
Konjunktion	{lemma}_konj	und_konj
Pronomen	{lemma}_pron	ich_pron
Artikel	{lemma}_art	der_art
Numerale	{lemma}_num	eins_num
Interjektion	{lemma}_int	hallo_int

성코드:
	•	nm = der
	•	nf = die
	•	nn = das

⸻

6.4 ID 유일성 규칙
	•	id 중복 절대 금지
	•	같은 의미면 기존 엔트리 재사용
	•	의미가 다르면 _1, _2, _3 순번 사용
	•	LLM 데이터 생성 시:
	•	기존 id 또는 lemma+pos 목록 제공 필수

7. LANG_CONFIG 스키마

언어별 입력/표기 규칙을 데이터로 관리

const LANG_CONFIG = {
  de: {
    input_rules: {
      case_sensitive: false,
      article_required: true,
      umlaut_variants: {
        "ä": ["ae"],
        "ö": ["oe"],
        "ü": ["ue"],
        "ß": ["ss"]
      },
      accents_optional: false
    },
    orthography: {
      capitalization: "NOUN_CAP"
    },
    punctuation_normalize: {
      apostrophe_variants: ["’", "'"],
      hyphen_variants: ["‐", "-"],
      dot_variants: ["·", "."]
    }
  }
};

8. 정답 판정 정규화 파이프라인 (checkAnswer)

expected 값 규칙
	•	typing_de 모드 기준:
	•	명사 + article_required=true → "${gender} ${lemma}"
	•	그 외 → "${lemma}"

⸻

파이프라인 구조
	1.	Trim / 공백 정리
	2.	대소문자 처리
	3.	문자 치환 (umlaut/악센트)
	4.	관사 처리
	5.	최종 문자열 비교 (===)

checkAnswer(user, expected, lang, word)
